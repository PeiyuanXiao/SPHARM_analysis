This repository is the research compendium for the following paper:

> Peiyuan Xiao, Hao Li, Ben Marwick (2025). *Characterizing core
> morphology and scar patterning within a unified spherical harmonic
> framework*. Submitted to *Journal of Archaeological Method and
> Theory*.

The compendium presents a unified spherical harmonic (SPHARM) framework
for jointly characterizing two properties of lithic cores: their
three-dimensional **morphology** (M-SPHARM, derived from surface meshes)
and the spatial structure of their **scar patterning** (SP-SPHARM,
derived from kernel-density estimates of scar orientation vectors on the
sphere). These descriptors are benchmarked against established
scar-pattern metrics (SPI and fabric analysis), tested for rotational
invariance, and applied to both experimental and archaeological core
assemblages.

------------------------------------------------------------------------

### 📁 Contents

The **analysis** directory contains all materials needed to reproduce
the study:

- [:file_folder: paper](.\analysis/paper): Quarto source for the
  manuscript ([`manuscript.qmd`](.\analysis/paper/manuscript.qmd)), the
  bibliography (`references.bib`), and the rendered `manuscript.docx`.
  All figures, tables, and in-text statistics are drawn directly from
  the `targets` pipeline via `tar_read()`.

- [:file_folder: data](.\analysis/data):

  - `raw_data/` — scar-orientation and core-metric data, including Lin
    2024 experimental scar vectors (`Lin_2024_scar_data/`),
    `Scar_orientation_data.xlsx`, and `SDG_core_metric.xlsx`.
  - `3D_models_cores/` — core meshes in `.stl` format (not version
    controlled; see [Data](#data) below).
  - `derived_data/` — intermediate and final output files (power
    spectra, ILR scores, statistical tables); fully regenerated by the
    pipeline.

- [:file_folder: scripts](.\analysis/scripts): all analysis code.

  - **SPHARM_main** — pipeline entry points:
    [`SPHARM_main.py`](.\analysis/scripts/SPHARM_main/SPHARM_main.py)
    (batch M-SPHARM of core meshes) and
    [`kde_to_spharm_main.py`](.\analysis/scripts/SPHARM_main/kde_to_spharm_main.py)
    (scar vectors → spherical KDE → SP-SPHARM).
  - **SPHARM_modules** — supporting Python modules for mesh
    preprocessing, PCA alignment, spherical-harmonic computation and
    power spectra, spherical KDE, shape reconstruction, and statistics.
  - **r_alignment / r_spharm / r_statistics / r_validation / r_utils** —
    R scripts for scar-vector alignment, power-order selection,
    statistical analysis (experimental and SDG cores), method and
    rotation validation, and shared utilities.
  - `environment.yml` — the conda environment (`spharm`) for all Python
    steps.

- [:file_folder: output](.\analysis/output): figures and other
  illustrations generated by the pipeline (not version controlled).

- [:file_folder: templates](.\analysis/templates): Quarto/Pandoc
  templates, the Word reference document, and the citation style (CSL).

The pipeline is defined in [`_targets.R`](.\_targets.R) at the project
root. It orchestrates three stages — **R preprocessing → Python SPHARM →
R statistics** — as a single reproducible
[`targets`](https://docs.ropensci.org/targets/) workflow.

### 🗄️ Data

The scar orientation and core metric data required to reproduce the
statistical results are included in this repository under
`analysis/data/raw_data/`.

The 3D core meshes (`.stl` files) are too large for version control and
are archived separately in the project's public OSF repository
(<https://doi.org/10.17605/OSF.IO/d82c5>). Download the `3D_models_cores`
folder from OSF and place its contents in:

    analysis/data/3D_models_cores/

so that each core mesh (e.g. `EXP01_Levallois preferential.stl`) sits
directly in that folder.

### 🚀 How to Reproduce the Analysis in a Docker Container

This compendium ships a [Dockerfile](Dockerfile) that builds the
complete computational environment — R 4.4 with RStudio and all required
R packages (restored from `renv.lock`), plus the conda `spharm`
environment for the Python SPHARM steps. Because both stacks are bundled
in a single image, the entire workflow can be reproduced with a single
`targets::tar_make()` call; the Python scripts do not need to be run
manually.

**Step 1 — Install [Docker](https://www.docker.com/get-started/)** on
your computer.

**Step 2 — Get the compendium.** Clone the repository:

    git clone https://github.com/PeiyuanXiao/SPHARM_analysis.git

or download the ZIP from GitHub (green `< > Code` button →
`Download ZIP`) and unzip it.

**Step 3 — Add the 3D models.** Download `3D_models_cores` from the data
archive (see [Data](#data)) and place the `.stl` files in
`analysis/data/3D_models_cores/`.

**Step 4 — Build the Docker image.** Run the following from the project
root (note the trailing `.`). This step may take some time, as it
restores all R packages and resolves the conda environment:

    docker build --platform=linux/amd64 -t spharm_analysis .

> **Note (Apple Silicon Macs):** The `--platform=linux/amd64` flag is
> required. The conda environment is locked to linux-64 package builds for
> numerical reproducibility, so the image must be amd64; without the flag,
> Docker on an Apple Silicon Mac would target arm64 and the conda solve would
> fail. With the flag, Docker runs the image under emulation (Rosetta 2) —
> slower, but results are bit-identical to the amd64 reference environment. On
> Linux and Windows/Intel hosts the flag is the native default and has no
> effect.

**Step 5 — Start the container.** The simplest approach is via Docker
Compose, which maps port 8787 and mounts the project at `/project`:

    docker compose up -d

Alternatively, with plain Docker:

*Linux/macOS:*

    docker run -d -p 8787:8787 -v $(pwd):/project -w /project -e PASSWORD=spharm spharm_analysis

*Windows (Git Bash):*

    MSYS_NO_PATHCONV=1 docker run -d -p 8787:8787 -v $(pwd):/project -w /project -e PASSWORD=spharm spharm_analysis

**Step 6 — Open RStudio.** Navigate to <http://localhost:8787/> in your
browser and log in with username `rstudio` and password `spharm`. The
project opens automatically at `/project`.

**Step 7 — Run the full pipeline.** In the R console:

``` r
targets::tar_make()
```

This executes every stage in dependency order and only recomputes
out-of-date targets:

- **Stage 1 (R):** align scar-direction vectors (SVD alignment, plus the
  Lin 2024 and rotation-perturbed alignments used for validation).
- **Stage 2 (Python):** batch M-SPHARM of core meshes, and spherical KDE
  → SP-SPHARM of scar vectors. Python targets run as separate processes
  against the conda `spharm` environment.
- **Stage 3 (R):** power-order selection, method comparison (SPI /
  fabric / SPHARM), rotational-invariance validation, and statistical
  analyses of the experimental and SDG core assemblages.

To build a single target and its dependencies, use e.g.
`targets::tar_make(spharm_analysis)`. To inspect the dependency graph,
run `targets::tar_visnetwork()`.

**Step 8 — Render the manuscript.** The paper is a Quarto document whose
prose is interwoven with code that reads results directly from the
pipeline. After `tar_make()` completes, render it to a Word document:

    quarto render analysis/paper/manuscript.qmd --to docx

Alternatively, open `analysis/paper/manuscript.qmd` in RStudio and run:

``` r
quarto::quarto_render("analysis/paper/manuscript.qmd")
```

**Step 9 — View the output:**

``` r
browseURL("analysis/paper/manuscript.docx")
```

**Step 10 — Clean up.** When finished, stop and remove the container:

    docker compose down

Or, if you started it with `docker run`:

    docker ps -aq | xargs docker stop | xargs docker rm
